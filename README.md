## Что это

**ruLiteLLM** — это **полный форк (хард-форк)** проекта [LiteLLM](https://github.com/BerriAI/litellm) (BerriAI, MIT).
Хард-форк означает, что мы ответвились от проекта ради собственного пути: не зеркалируем upstream
и не наследуем прямо его коммерческую (enterprise) часть — всё недостающее реализуем сами с нуля
в MIT-ядре и ведём ветку независимо.

## Цель форка

1. **Руссификация** — полный перевод админ-интерфейса на русский язык **штатным механизмом
   интернационализации** (i18next, заложенным в апстриме): перевод живёт в каталоге
   `ui/litellm-dashboard/src/i18n/locales/ru-RU.json`, а не заменой литералов в коде.
   Поддерживается мультыязычность: переключение RU/EN происходит на лету, через меню аккаунта,
   без перезагрузки страницы; для нового пользователя язык по умолчанию — ru-RU.
   В переведённых литералах продукт называется **ruLiteLLM** (идентификаторы, env-имена и URL не трогаем).
2. **Улучшение функционала своими силами** — недостающий функционал коммерческой версии
   реализуется с нуля в форке (прецеденты: лимит SSO-пользователей через env `LITELLM_SSO_FREE_USER_LIMIT`,
   гейт `/openapi.json` по сессии, скрытие FastAPI-доков: `NO_DOCS`/`NO_REDOC`/`NO_OPENAPI`).
3. **Эксплуатация у нас** — публичные репы не нужны, деплой из wheel/pip вместе с torch+CUDA,
   прод-развёртывание по нашему рунбуку.

## Что сделано нами (сверх апстрима)

Кратко, чем форк отличается от «легаси» LiteLLM — всё реализовано с нуля в MIT-ядре:

- **Полная руссификация админ-UI** (каталог `ru-RU.json`, ~14 000 строк, покрытие 100%,
  корректные русские формы множественного числа), переключение RU/EN на лету, бренд ruLiteLLM
  (знак — электричка, `rulitellm_mark.png` в шапке, на логине и экране загрузки).
- **«Мониторинг»** — живой дашборд вместо enterprise-аналитики: tok/s и TTFT по чанкам
  стрима (per-chunk `on_stream_chunk` в `streaming_handler`), префилл/генерация за
  60 мин (300 ячеек × 12 с), in-flight с TTFT и группировкой по «пользователь+ключ+модель»,
  IP/User-Agent, кулдауны роутера, счётчики с запуска; **прерывание live-запросов**
  (`POST /dashboard/abort`, модалка «подробно» — поштучно и все сразу).
- **«Мониторинг гардеев» (Request Gantt)** — gantt-диаграмма запросов в реальном времени:
  in-flight-реестр на CustomLogger-хуках, FIN-мост до записи в SpendLogs, живые
  пульсирующие дорожки.
- **«Журнал активности»** — замена enterprise-аудита: тепловая карта дни×часы, лента
  сессий, AI-оценка периода (свой интервал, клик по кирпичу = час, адресно по человеку),
  летопись оценок, экспорт в Markdown.
- **Гейты приватности/безопасности**: `NO_DOCS`/`NO_REDOC`/`NO_OPENAPI`, гейт
  `/openapi.json` по сессии, `LITELLM_SSO_FREE_USER_LIMIT` (лимит SSO-пользователей),
  мониторинг — только администраторам.
- **Наблюдаемость без Prometheus** — процессные метрики своего реестра (`/dashboard/state`),
  ничего внешнего опрашивать не нужно.
- **Heartbeat стрима** — пока апстрим молчит (долгий префилл), в SSE каждые 5 с идёт delta
  с пробелом (`sse_keepalive_ping_interval_seconds`), чтобы клиенты с idle-таймаутом стрима
  не рвали соединение на 20–30-й секунде.
- **Отмена при дисконнекте** — если клиент оборвался, генерация у движка останавливается
  сразу (`http.disconnect`), слоты не занимают «призраки».
- **Дашборд не зависит от очередей** — `/dashboard/state`, `/dashboard/abort` и гантт
  не пропускаются через admission control, «Прервать все» работает при занятых слотах.
- **Приватность стриминга** — хук `on_stream_chunk` (питает Мониторинг) уважает политику
  логирования: при `no-log` контент запросов не подглядывается.

## Ветки

- `transition-1.110.x` — основная линия разработки (база — апстрим 1.110.2), default-ветка GitHub,
  с неё живёт прод.
- `main` / `sync-1.102.4` — архив легаси-линейки 1.102.x (эпоха перевода заменой литералов).

## Деплой (наш прод)

Прод — нативная установка в LXC-контейнер (без docker): venv + uv, PostgreSQL, systemd-юнит,
UI собирается (`npm ci && npm run build`) и укладывается в `litellm/proxy/_experimental/out`.
Смена версии на проде — только через git-клон и скрипты `rl-git-{status,diff,deploy}`
(сверка клона с живым кодом, dry-run, бэкап затронутых файлов, md5-контроль, рестарт по флагу).

## Быстрый старт

```bash
pip install litellm[proxy]        # установка из wheel вместе с torch+CUDA
litellm --model <псевдоним> --api_base <url>   # запуск шлюза
```

Далее в браузере откроется локализованный админ-интерфейс ruLiteLLM (вкладка «ruLiteLLM Dashboard»).
Полное описание возможностей ядра (AI Gateway, SDK, список 100+ провайдеров, MCP/A2A, гардрейлы,
budgets/keys) — в [документации LiteLLM](https://docs.litellm.ai/docs/simple_proxy); форк наследует
MIT-ядро и переводит его UI, а не переписывает API.

## Локализация UI (цикл перевода)

На линии 1.110 перевод — это просто правка каталога `src/i18n/locales/ru-RU.json` (ключи
берутся из `en.json`, сборщик каталога и сверка покрытия — в `tools/rulitellm/i18n`).
Сканер остатка и очередь — в репозитории-вики (`tools/i18n-scan/scan.mjs`, `out/todo.txt`,
`out/baseline.json`); глоссарий и норма перевода — в `wiki/answers/litellm-ui-i18n.md`.
В легаси-линейке 1.102.x (архив) перевод сделан заменой литералов в JSX, там цикл был
пачками по файлам через карту EN→RU.
